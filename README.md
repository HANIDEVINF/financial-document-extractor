# Financial Document Router & Extraction Demo

This is a browser-based demo combining a Keras document-type classifier with lightweight text/field extraction logic.

> **Important evaluation limitation:** the router is trained on synthetic, template-generated financial text. The repository's reported 100% accuracy and macro-F1 measure a held-out split from that synthetic generator only; they do not demonstrate performance on real invoices, bank statements, payslips, scanned PDFs, or varied layouts. The UI is a prototype, and extracted values require human verification.

## What is implemented

- A Keras neural classifier for nine generated document categories, including an unknown class.
- A training script that builds the synthetic corpus and writes classification metrics.
- A browser UI for experimenting with pasted text and TXT, CSV, JSON, and PDF input.
- Lightweight field-extraction heuristics and confidence/unknown handling.

The model router and field extraction are distinct parts: the classifier predicts a document category; it does not by itself guarantee accurate extraction of all financial fields.

## Run locally

Requires Node.js/npm. To regenerate the classifier, use a compatible Python environment with TensorFlow, NumPy and scikit-learn.

~~~bash
npm ci
npm run dev
~~~

Open the address printed by the development server. The static application is served from the public directory.

To regenerate synthetic training data, train the router and update the exported model artifacts:

~~~bash
python scripts/train_keras_financial_router.py
npm run build
~~~

## Current limitations

- Training/evaluation examples are generated by templates, with strong lexical patterns; metrics are likely optimistic for real documents.
- The current experiment does not establish generalization to real, held-out business documents.
- PDF text extraction is not equivalent to OCR; scanned pages require a separate OCR pipeline.
- No financial or accounting output should be accepted without human validation.
- The project is a prototype, not a production accounting/compliance system.

## Reproducible evaluation to add next

Use a separate, legally sourced and de-identified set of real documents; split by document/template/vendor to limit leakage; annotate fields; and report document-type macro-F1 separately from per-field exact match, precision/recall, missing-field behavior and abstention quality.
